# Структура репозитория

| Каталог | Назначение |
| --- | --- |
| `client/` | Qt/QML-клиент, протоколы и серверные сценарии |
| `service/` | Привилегированная служба и управление сетью |
| `common/`, `ipc/` | Общий код и межпроцессный интерфейс |
| `installer/` | Исходники установщика Windows |
| `launcher/` | Исходники Build Studio |
| `deploy/` | Упаковка и необходимые бинарные зависимости форка |
| `tools/` | Поддерживаемые инструменты разработки и обслуживания |
| `tests/` | Проверки и инструкции к ним |
| `docs/` | Документация, изображения, отчёты расследований |
| `metadata/` | Метаданные распространения приложения |

## Локальные файлы

- `dist/`: готовые EXE/APK Windows/Android. Публикуются через GitHub Releases, не через Git.
- `.local/`: личная диагностика, старые журналы, результаты локальных проверок и черновики. Не публикуется и не удаляется очисткой.
- `docs/releases/`: публичные описания изменений и ограничений выпусков.
- `build/`, `build-installer/`: кэши компиляции. Не переносить: CMake хранит абсолютные пути.
- `.venv/`: локальное Python-окружение. Очистка его сохраняет.

Корневые `build_installer.ps1`, `build_android.ps1`, `build_env.ps1` и `build_env.sh` остаются стабильными точками входа для Build Studio и существующих инструкций. Android использует короткий путь `C:\avpn` для промежуточной сборки; очистка проекта его не затрагивает.

## Очистка

Закройте сборки и запущенные из build-каталогов приложения.

```powershell
# Посмотреть список и объём временных файлов
.\tools\clean-workspace.ps1
# Удалить промежуточную упаковку и кэши .NET, сохранив компиляцию Qt
.\tools\clean-workspace.ps1 -Apply
# Дополнительно удалить кэши CMake и Android в deploy (следующая сборка будет полной)
.\tools\clean-workspace.ps1 -IncludeBuildCaches -Apply
```

Очистка использует фиксированный список каталогов, проверяет границы проекта, отказывается удалять отслеживаемые Git файлы и переходить по junction/symlink. `-WhatIf` также поддерживается. Сбой удаления занятого файла возвращается как ошибка.

Windows-сборщик удаляет свой временный staging в `finally`, включая выход по ошибке. Payload и каталог публикации можно очистить указанной командой после сборки; они нужны при диагностике неудачной упаковки. Удаление файла из рабочего дерева не удаляет его из истории Git.
